# Autoresearch Harness 設計

- 日期：2026-10-22
- 專案：`screener`
- 狀態：草稿，待使用者確認

## 1. 目的

使用者手動回測後發現，RS v1 在 2021–2026 的整體績效最好。使用者想讓 agent 自動反覆實驗：以現有的選標的邏輯為基礎，修改或組合它們，並找出適合的進場邏輯。比較基準是「相同回撤下的總報酬」。

架構參考 Karpathy 的 autoresearch：評分器固定，agent 只能改一個檔案，每輪改一處，分數變好才留下。

## 2. 目標

1. 離線回測涵蓋 2021-01-01 到 2026-10-22。
2. 每個候選版本都在總回撤 24%–26% 下比較總報酬。
3. 迴圈自動執行：agent 改程式 → 腳本回測 → 腳本評分 → 留或丟。
4. 結束時列出前三名，不只第一名。

## 3. 非目標

- 不處理已下架的合約（使用者決定）。
- 不留驗收段（holdout）。每輪都跑全期間（使用者決定）。
- 不自動把結果部署到實盤。採用哪個版本由使用者手動決定。

## 4. 反目標（技術上能跑，但算失敗）

- agent 能改到評分、回測、資料或部位大小。這樣分數不可信。
- 實驗改到 `main` 分支，或影響 pm2 上正在跑的 `crypto-screener`。
- 分數靠極少交易撐起來。
- agent 寫出偷看未來資料的程式碼，而且沒被抓到。
- （我的推測）前三名只是同一個版本的微小參數差異，無法幫使用者判斷過擬合。

## 5. 使用者的決定

### 5.1 資料

- 期間：2021-01-01 00:00 UTC 到 2026-10-22。結束日固定，每輪都一樣。
- 選股池：只用現在還在交易的 USDT 永續合約。已下架的不管。

### 5.2 評分規則

1. 每一輪都跑全期間。
2. 用部位大小控制回撤。總回撤（MDD）必須落在 24%–26%。例外：r = 5% 時總回撤仍低於 24%，這個版本用 r = 5% 參加比較（我的決定，見 6.3 第 6 點）。
3. 有以下任一種情況就淘汰：
   - 總回撤調不進 24%–26%（上面的例外不算）。
   - 交易筆數 ≤ 100。
   - 任一幣種的單獨回撤 > 40%。定義：把該幣每筆交易的 `ret_pct` 依出場時間連乘，假設全部資金只交易這個幣，取最大回撤。這個值和部位大小無關。
   - 另外 3 種淘汰情況是我的決定：權益 ≤ 0（6.3 第 7 點）、偷看未來（6.4 第 8 點）、固定百分比止損（6.4 第 9 點）。
4. 通過淘汰的版本比總報酬(%)。

### 5.3 agent 的範圍

- 以現有 5 種選標的邏輯為基礎，修改或組合：
  - RS v1：`strategy/shotgun_v3.py` 的 `rs_score`
  - RS v2：`strategy/shotgun_v3.py` 的 `rs_score_v2`
  - 鱷魚 50／鱷魚 233：`strategy/shotgun_v3.py` 的 `alligator_4h_score`（`require_233=False`／`True`）
  - Martin30：`strategy/shadow_lists.py` 的 `martin30`
- 找出適合的進場邏輯。
- 不限定現在實盤用的 4h 鱷魚 233。
- 開單時框：agent 可以從 5m、15m、30m、1h、2h、4h、8h 中選一個。目的是找出更好的配置。

### 5.4 輸出

- 列出前三名，不只第一名。原因：使用者擔心過擬合。

### 5.5 止損規則

- 每筆開單都必須有一個固定的嚴格止損。
- 每筆開倉的上限：如果打到開倉時的嚴格止損，虧損最多是總權益的 5%。
- 止損只能上調，不能下調。策略只做多，所以止損只會越來越靠近開倉價，或高於開倉價。
- 止損怎麼上調屬於策略邏輯，agent 可以改。
- 初始止損由 agent 決定。它必須用常用指標算出來（例如 ATR、前波低點、均線），不能用「開倉價 − n%」。
- 部位大小用 r 反推：部位 = 總權益 × r / 初始止損距離，r ≤ 5%。
- 總曝險上限 400%。開新倉會超過上限時，跳過這筆開倉，就像帳戶保證金不夠。

## 6. 我的決定（使用者可推翻）

### 6.1 資料

1. 基礎資料是 5m K 線。其他時框（15m、30m、1h、2h、4h、8h、1d）都從 5m 重新取樣。原因：所有時框來自同一份資料，不會互相矛盾。Binance K 線以 UTC 對齊，重新取樣的結果應該和 API 直接給的一樣，builder 要抽查確認。
2. 下載：已結束的月份用 `data.binance.vision` 的月檔 zip（`data/futures/um/monthly/klines/<SYMBOL>/5m/`）。當月用 `/fapi/v1/klines` 加 `startTime` 分頁補齊，沿用 `tools/backtest_compare.py` 的 `_http_get_json`。原因：每個幣約 61 萬根 5m K 線，只用 API 要約 24,000 次請求、至少 100 分鐘。
3. 快取放在 `data/backtest_cache/`，每個幣一個檔。之後執行只補缺少的 K 線。
4. 選股池沿用 `get_liquid_universe()` 的篩選：今天成交量前 60 大，排除穩定幣和美股代幣。
5. 2021 年以後才上市的幣，上市前沒有 K 線，所以上市前不會入選。builder 要確認 `build_daily_lists()` 在歷史不足時會跳過該幣。
6. 估算：60 個幣 × 約 61 萬根 5m K 線。用現有 JSON 格式約 5 GB，太大。快取要用壓縮的二進位格式，格式由 builder 決定。
7. 選股池在第一次執行時存成固定清單檔，之後不再更新。原因：`tickers_24h` 快取（`tools/backtest_compare.py:75`）每次 `--refresh` 都會變，不同輪次的分數會不可比。
8. 暖機：K 線從 2020-11-01 開始抓。BTC 從 2020-01-01 開始抓，讓 2021-01-01 當天已有 250 根以上（`tools/backtest_compare.py:291` 的門檻）。只有 2021-01-01 以後開倉的交易才計分。

### 6.2 回測

1. 回撤改成每小時用收盤價計算權益，包含持倉浮虧。現在只在平倉時計算（`tools/backtest_compare.py:193`–`195`）。
2. 止損成交沿用現行為：開單時框的 K 線低點碰到止損，就以止損價成交（`tools/backtest_compare.py:183`）。不模擬跳空滑價。
3. 出場邏輯 `exit_signal`（SMMA10 < SMMA20）鎖定，agent 不能改，但它在 agent 選的開單時框上計算。原因：使用者只提到「開單邏輯」。
4. 手續費沿用 `TRANSACTION_FEE_PERCENT`。不模擬資金費率。
5. BTC 日線 EMA200 多頭開關：實盤只在 `bull` 為 True 時開倉（`strategy/shotgun_v3_live.py:120`、`:168`），當天沒有名單時預設不開倉（`:129`）。baseline 照實盤帶開關，用 BTC 日線逐日計算。開關屬於進場邏輯，所以 agent 可以改。
6. 「止損只升不降」由腳本強制，不靠 agent 遵守。每根開單時框 K 線收盤後，腳本把止損設成 `max(舊止損, candidate 給的新止損)`。
7. 新止損從下一根 K 線開始生效。原因：避免用同一根 K 線的高點上調止損，又用同一根的低點出場（look-ahead）。
8. 4h 視窗對齊實盤：實盤每天只抓最近 300 根 4h K 線（`strategy/shotgun_v3_live.py:69`、`:71`）。`rma_seeded` 的結果和視窗長度有關（`strategy/shotgun_v3.py:20`–`29`），SMMA233 在 300 根時還沒收斂。所以每個回測日只用當天以前最近 300 根 4h K 線。原因：回測算出的名單要等於實盤會算出的名單。
9. 視窗長度可以當成 candidate 的參數。agent 改了它，部署時實盤也要跟著改，報告要標出來。

### 6.3 部位換算（控制回撤）

依據：單筆最大虧損等於部位大小 × 初始止損距離。止損只升不降，所以這個上限不會變大。因此回撤大約和每筆風險成正比。

腳本調整的是每筆風險 r：打到初始止損時，虧損佔開倉當下總權益的 %。部位大小 = 總權益 × r / 初始止損距離。現行的 `NOTIONAL_PCT = 0.20` 搭配 20% 止損，等於 r = 4%（`config.py:91`）。

1. 第一次用 r = 4% 跑，量出總回撤。
2. 下一次的 r = 這一次的 r × 25 / 這一次的總回撤(%)。
3. r 上限是 5%（使用者決定，見 5.5）。換算結果超過 5% 時，用 5%。
4. 複利讓這個關係不完全線性。比例換算 2 次還不在 24%–26%，就在已知的上下界之間二分搜尋。
5. 每輪最多跑 5 次回測。
6. 判定：
   - 總回撤落在 24%–26%：通過這一條。
   - r = 5% 時總回撤仍低於 24%：通過這一條，用 r = 5% 的總報酬參加比較。這個版本在比較低的回撤下和別人比，對它不利，所以不會灌水。（我的決定，是 5.2 第 2、3 條的例外。）
   - 其他情況：淘汰。
7. 任何一次回測的權益變成 0 或負數，就淘汰。
8. r 只由腳本設定，agent 不能改。

### 6.4 agent 只改一個檔案

1. 新增 `strategy/candidate.py`。agent 只能改這個檔案。
2. 這個檔案提供四件事：每日選標的的評分、開單時框與該時框上的進場判斷（含 BTC 開關）、開倉時的初始止損、持倉中的止損上調。介面由 builder 定，但要能表達現有 5 種選標的邏輯。
3. 它可以 import `strategy/shotgun_v3.py` 和 `strategy/shadow_lists.py` 的函式，但不能改那兩個檔案。
4. 原因：實盤程式碼不會被改動。每個版本就是這一個檔案的差異，容易比較和保存。
5. 每輪結束時，腳本檢查工作目錄。除了 `strategy/candidate.py` 還有其他程式碼變更，就淘汰並還原。腳本自己的產出（例如 `results.tsv`）不算。
6. agent 可以改：Top N（`RS_TOP_N`）、`ER_MIN`、SMMA 長度、其他進場過濾條件、初始止損、止損上調方式。agent 可以使用快取裡的任何 K 線資料（各幣 5m 到 1d 的所有時框，BTC 也一樣），不能引入其他資料來源。
7. agent 不能改：每筆風險 r、總曝險上限（見 5.5）、出場邏輯 `exit_signal`。
8. 防偷看未來：腳本每輪做一次前綴檢查。把資料在幾個隨機時間點截斷，重新跑 candidate。截斷點以前的名單、進場訊號、止損必須和完整資料的結果一模一樣。不一樣就淘汰。原因：`simulate_arm` 先對整段序列算指標（`tools/backtest_compare.py:158`），candidate 拿到整段陣列就可能偷看未來。
9. 固定百分比檢查：把每筆交易的初始止損距離（佔開倉價的 %）四捨五入到 0.1%。95% 以上的交易距離都一樣，就判定為「開倉價 − n%」，淘汰。

### 6.5 迴圈

1. 一個 Python 腳本控制迴圈。每輪呼叫一次 `claude -p`，提供 `program.md`（agent 指示）和最近的 `results.tsv`。
2. agent 每輪只試一個想法。
3. 回測、部位換算、評分、留或丟，全部由腳本做。腳本不解析 agent 的輸出。原因：使用者環境的 poemer Stop hook 會在 `claude -p` 的輸出後面附加文字。
4. 第 0 輪（baseline）：腳本把現有 5 種選標的邏輯配上現行進場邏輯，各跑一次。分數最高的當起點。baseline 沿用現行的固定 20% 止損，只當參考點，不做固定百分比檢查。所以 agent 從起點改的第一件事，通常是把止損換成指標算出來的。
5. 每輪都從目前第 1 名的版本開始改。分數高於第 1 名才取代它。
6. 輪數上限用 `--rounds` 設定，預設 30。Ctrl-C 可以隨時停止，已完成的輪次保留。
7. 隔離：在獨立的 git worktree 和分支（例如 `autoresearch/2026-10-22`）上跑。

### 6.6 記錄與前三名

1. 每輪寫一列到 `results.tsv`。欄位：輪次、一句話說明改了什麼、最後的每筆風險 r、總回撤、總報酬、交易筆數、最大單一幣種回撤、勝率、獲利因子、結果、版本 ID。
   - 結果 `keep`：成為新的第 1 名。
   - 結果 `pass`：通過淘汰，但沒贏第 1 名。
   - 結果 `discard`：被淘汰，或執行失敗。
2. 每個 `keep` 或 `pass` 的版本，都保存 `strategy/candidate.py` 的內容。保存方式（git commit 加 tag，或檔案副本）由 builder 決定。
3. 結束時輸出報告：總報酬前三名。每一名附上：
   - 和 baseline 的 diff。
   - 逐年（2021…2026）的總報酬和回撤。用同一次回測的交易紀錄計算，不另外跑。
   - 獲利最多的 3 個幣，各自佔總獲利的比例。只顯示，不拿來淘汰。
   - 原因：使用者擔心過擬合。逐年表現差很多的版本，或前三名幾乎一樣，使用者一眼就能看出來。

## 7. 留給 builder 決定

- 檔案位置和切分，例如腳本放在 `tools/` 還是 `autoresearch/`。
- `strategy/candidate.py` 的介面細節。
- `program.md` 的內容。
- 快取格式（JSON 或更省空間的格式）。
- 每輪太慢時的回測效能優化。
- `claude -p` 的參數（模型、權限、timeout）。

## 8. 已知風險

1. 倖存者偏差：只用現存的幣，結果偏樂觀。使用者已接受。
2. 過擬合：沒有驗收段。用前三名和逐年拆解緩解。
3. 跳空：止損一定成交在止損價。實際成交可能更差，例如 2021-05-19 的大跌。
4. 槓桿：總曝險上限 400% 會讓部分訊號被跳過。名單裡的開倉順序會影響結果，builder 要用固定、可重現的順序（例如沿用現在的 `sorted(gate)`）。
5. 每輪時間未知：5m 開單時框時，每次回測要走過約 61 萬個時間點、最多 60 檔，每輪最多 5 次回測，另外還有前綴檢查。`rma_seeded` 是純 Python 迴圈（`strategy/shotgun_v3.py:20`–`29`），在 5m 上會很慢。需要實測，太慢就優化。
6. 記憶體：60 檔 × 61 萬根 5m K 線，用 float64 載入約 1.8 GB。
7. 用量：每輪呼叫一次 `claude -p`。30 輪的用量要在第一次執行時量測。

## 9. 未決（待使用者決定）
